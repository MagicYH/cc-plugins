# 根任务生命周期

覆盖命令：`init`、`show`、`start`、`status`、`output`。只操作根任务；根任务的工作群就是来源群（根群），不建新群。

| 编号 | 场景 | 步骤 | 预期 |
| --- | --- | --- | --- |
| R1 | 在普通群创建根任务并写入全部字段 | `init --title --desc --criteria --priority 高 [--from 派发人]`，再 `show` | 成功，返回的 `chat_id` 是来源群；工作群是来源群；负责人是执行测试的 bot，状态进行中，优先级高，当前进展为 `[MM-DD HH:mm] 进行中：创建任务`；没有父任务、子任务数 0；来源群的群名没有被改；设置了派发人时 `dispatcher.open_id` 等于派发人 |
| R2 | 不传优先级和派发人 | `init` 不带 `--priority`、`--from`，会话发起人为空 | 优先级为"中"；派发人为空 |
| R3 | 派发人取会话发起人 | `init` 不带 `--from`，会话发起人设为派发人 | 派发人等于会话发起人（未设置派发人时跳过） |
| R4 | 对进行中的任务执行 start | `start` | 成功，状态仍是进行中 |
| R5 | 根任务改为阻塞 | `status 阻塞 --note <原因>` | 成功，`notified` 为 true；根群里有"任务「<标题>」（<ID>）受阻：<原因>"；当前进展为 `… 阻塞：<原因>` |
| R6 | 对阻塞的任务执行 start | `start` | 成功，状态仍是阻塞 |
| R7 | 阻塞后恢复进行中，不带说明 | `status 进行中` | 成功，`notified` 为 false；当前进展为 `… 进行中：继续处理` |
| R8 | 写入产出 | `output <内容>`，再 `show` | 成功；产出等于写入的内容 |
| R9 | 没有子任务的根任务直接完成 | `status 已完成 --note <说明>` | 成功，`notified` 为 true；状态已完成；根群里有"任务「<标题>」（<ID>）已完成：<说明>"，设置了派发人时这条消息 @ 了人 |
| R10 | 对已完成的任务执行 start | `start` | 成功，状态仍是已完成 |

单聊、话题群里不能 `init` 的情况见 `errors/` 的 E2。
