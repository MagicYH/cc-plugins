# 子任务与工作群

覆盖命令：`add`、`children`、`show`。重点是第一次建子任务时自动建工作群，以及二级拆分时建下一级工作群。

| 编号 | 场景 | 步骤 | 预期 |
| --- | --- | --- | --- |
| S1 | 根任务第一次建子任务 | `init` 建根任务，再 `add <根任务>` | 成功，`chat_created` 为 true；根任务的工作群等于返回的 `chat_id`；群名等于根任务标题；群描述为 `muxboard task=<根任务ID> upper=<来源群ID>`；群里有说明消息"本群是任务「<根任务标题>」（<根任务ID>）的工作群" |
| S2 | 再建一个子任务 | `add <根任务>` | 成功，`chat_created` 为 false，`chat_id` 与 S1 相同 |
| S3 | 子任务的初始字段 | `show <子任务>` | 状态待分配，负责人为空，父任务是根任务，优先级默认"中"；传了 `--priority 低` 的子任务优先级为"低" |
| S4 | 列出子任务 | `children <根任务>`，加 `--status 待分配`、`--status 已完成` | 分别返回 2、2、0 条 |
| S5 | 子任务计数 | `show <根任务>` | `children.total` 为 2，`children.done` 为 0 |
| S6 | 二级拆分 | `add <子任务A>` | 成功，`chat_created` 为 true；群名为"<根任务标题> - <子任务A标题>"；群描述里的上级群是根任务的工作群；群里有说明消息 |
| S7 | 上级群里的人被拉进新群 | 对比来源群和根任务工作群的成员 | 工作群里的人包含来源群里的人（最多 50 个）；来源群里没有人时跳过 |
